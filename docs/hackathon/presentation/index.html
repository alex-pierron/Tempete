3. Model Equality · 1/3

La question : quels endpoints servent le même modèle ?

33 déploiements LLM, chacun derrière son endpoint, ep-01 à ep-33.

  • Pour chaque endpoint : à quelle famille appartient-il (même modèle de base) ?
  • Pour chaque paire : servent-ils le même modèle ?
À retenir Même modèle = même checkpoint + même quantization + même adaptateur LoRA. Une même famille ne suffit pas.
Ne change pas l'identitéChange l'identité
Watermark de décodageModèle de base
System prompt du fournisseurQuantization (exemple : fp8)
Stratégie de décodage (température...)Adaptateur LoRA, même à une autre force

Entraînement gratuit : ref-01..ref-09

Jamais notés, réponses publiées (practice_answers.csv). Un modèle S décliné en plain, system prompt, persona, watermark, température 1,0, plus 4 variantes : T1 fp8, T2 LoRA 0,3, T3 LoRA 0,7, T4 LoRA 1,5.

3. Model Equality · 2/3

La métrique et les contraintes

MCC = TP·TN − FP·FN√(TP+FP)(TP+FN)(TN+FP)(TN+FN)
score = 0,1 · MCCfamille + 0,9 · MCCmodèle
  • 528 paires (i < j) ; chaque MCC est borné à 0 par max(0, MCC).
  • Famille (10 %) : la paire est-elle de la même famille ? Toutes les paires.
  • Modèle (90 %) : même modèle ? Seulement les paires d'une même famille vraie.
  • Faux « même » et « différent » manqués baissent tous deux le score.
À retenirReconnaître seulement les familles rapporte au plus 0,1. L'essentiel se joue sur les variantes quantifiées et LoRA.

3. Model Equality · 3/3

Notre méthode et le plan de budget

Méthode (papier MET, Gao, Liang, Guestrin)

  1. Mêmes prompts sur chaque endpoint (banque de 92 prompts, 8 catégories), choisis là où fp8 et LoRA changent le texte tiré et où les déguisements le changent peu.
  2. Pour chaque paire : MMD à noyau de Hamming, comparé à un test par permutation, résumé en z-score.
  3. Calibration sur les ref-* (gratuits), puis regroupement à 2 niveaux : familles, puis modèles.
Non vérifiéLa puissance réelle de la méthode sur fp8 et LoRA : les tests utilisent un modèle jouet. On le saura sur les ref-*.

3. Unlearning · 1/3

La question : faire oublier 3 500 images

Rendre un modèle qui se comporte comme s'il n'avait jamais vu ces 3 500 images, tout en restant bon sur le reste.

  • La cible est un modèle « gold » : réentraîné sans le forget set, moyenne de plusieurs réentraînements.
  • Il faut imiter la confiance et la classe fausse choisie, image par image, sur les images exactes et sur des copies légèrement modifiées (cachées).
  • Seuls le modèle original et le forget set sont fournis : pas de données de rétention.
Interdit en pratiqueLa montée de gradient naïve abîme le modèle et reste distinguable du gold : le sujet la pénalise.

Données

model.ptstate dict timm vit_base_patch16_224, 100 classes, LayerScale 1e-4 ; 85 893 988 paramètres
forget_images.npzclé images, uint8 [3500, 224, 224, 3], valeurs 0 à 255, sans labels
SourceSprintML/unlearning sur Hugging Face (public)
Sur le disque343 617 075 octets (modèle), 526 848 266 octets (forget set)

Sur ce poste : modèle et forget set téléchargés, sha256 vérifié. Le contrôle de format validate accepte model.pt (343,6 Mo, 176 tenseurs).

3. Unlearning · 2/3

La métrique : une distance au modèle gold

final = forget × retain
forget = mean_std × prediction
mean_std = 1 − clip( dsubdorig, 0, 1 )
avec dm = |moy(Lm) − moy(Lgold)| + |σ(Lm) − σ(Lgold)|, σ = écart-type
prediction = 1 − clip( KL(pgold ‖ psub)KL(pgold ‖ porig), 0, 1 ) softmax à T = 2
retain = clip( accsubaccorig, 0, 1 ) × 11 + KL(porig ‖ psub)
Porte d'utilité Moins de 70 % d'accuracy sur un validation set caché : forget et retain mis à 0, quel que soit le reste.
  • forget est moyenné sur les images exactes et sur des copies altérées cachées, à parts égales.
  • L est la perte d'entropie croisée avec le vrai label ; acc est mesurée sur un control set caché.
  • 0 = rien oublié (sub = orig). 1 = identique au gold.
À retenirÊtre « plus faux » que le gold est pénalisé comme ne pas bouger. Le score est une distance au gold, pas un taux d'oubli.

3. Watermark Localization · 1/3

La question : où est le tatouage dans l'image ?

Rendre un masque binaire : 1 = zone tatouée, 0 = zone propre.

  • Chaque image a été tatouée par PixelSeal, TrustMark ou StegaStamp sur un sous-rectangle (rapport d'aspect au plus 16:1, et 2:1 pour TrustMark).
  • Puis éditée : le tatouage est écrasé ou ajouté par endroits.
  • Ces trois méthodes décodent un seul message pour l'image entière : elles ne sont pas entraînées à localiser.
Enjeu (sujet officiel)Sans localisation, une édition ajoutée par un tiers est attribuée au propriétaire du tatouage.

Les quatre éditions

Outpaintingl'image est étendue ; le tatouage complet reste, sur une partie seulement
Retrait / altération d'objetun trou dans le tatouage
Ajout d'objetun objet non tatoué couvre le tatouage : un trou
Transplantationun objet tatoué est collé dans une image propre : le tatouage n'est que sur lui

Éditions larges (la moitié de l'image) à fines (un objet mince, un visage). Les trois méthodes se comportent très différemment : pas de solution unique attendue.

3. Watermark Localization · 2/3

Les données et la métrique

1 530 images PNG, réparties à égalité entre les 3 méthodes

ImagesContenu
Train510170 par méthode : image, masque (512 et 128), méthode, message embarqué
Test1 020340 par méthode : image, méthode, message embarqué (pas de masque)
À retenirAu test, on connaît la méthode et le message de chaque image : on peut chercher ce message précis.

Grille d'évaluation 128 × 128 : une cellule = 4 × 4 pixels ; vérité = 1 si au moins 50 % de ses pixels sont tatoués.

Score : mIoU sur 2 classes, par image

IoUc = |Pc ∩ Gc||Pc ∪ Gc|, c ∈ {0, 1}
mIoUimage = ( IoU0 + IoU1 ) / 2
  • Si l'union est vide pour une classe, son IoU vaut 1.
  • Score = moyenne de mIoUimage sur toutes les images : chaque image compte pareil, quelle que soit la taille de l'édition.
  • Les faux positifs et les faux négatifs agrandissent l'union : les deux sont pénalisés.

4. Keynote de Meta · 1/3

Un tatouage global ne dit pas où il est

Pierre Fernandez (Meta FAIR), « Invisible image watermarking, between research and production », 21/11/2026, 57 slides. Numéros entre crochets : slides de la keynote.

  • Un tatouage global donne une seule réponse par image. Après inpainting, collage ou fort recadrage, l'extracteur moyenne sur toute l'image : il ne dit ni où est le tatouage, ni ce qui a changé [24].
  • Watermark Anything (WAM) traite le tatouage comme une segmentation : quels pixels sont tatoués, et quel message ils portent [25-35].
  • Ses extracteurs sortent une carte par pixel, 256 × 256 × (1 + nbits), avant toute moyenne [29, 32].
À retenirC'est exactement le sujet de la tâche Watermark Localization.

Les extracteurs Video Seal et Pixel Seal ont la même structure de sortie, B × (1 + nbits) × H × W avant mise en commun : vérifié dans le code Meta

D'où la piste de la page 15 : lire cette carte avant la moyenne, et la comparer au message connu.

4. Keynote de Meta · 2/3

Pixel Seal travaille en 256 × 256 ; la détection est un test

Pixel Seal [17-22]

  • L'image est redimensionnée en 256 ; l'embedder produit un résidu atténué par une carte JND (différence juste perceptible) ; le résidu est remis à la taille d'origine [17-19].
  • L'extracteur redimensionne aussi en 256 [17].
  • Pas de perte perceptuelle : un discriminateur la remplace [20]. Code MIT, github.com/facebookresearch/videoseal [22].
Conséquence pour nousLa résolution effective d'une carte de présence est celle de l'extracteur, pas celle de l'image 512 × 512.

Détection [14, 15]

  • Test sur la bit accuracy : sous H0 (image naturelle), les bits sont aléatoires et la p-valeur est une somme binomiale.
  • Exemple de la keynote : 31/32 bits corrects pour une image générée, 17/32 pour une image naturelle [14].
Seuil τTPRFPR
0,800,504·10-4
0,900,164·10-6

Dans wmkit : seuil binomial de 167/256 bits pour p < 1e-6.

Unlearning : un state dict float32, sous la porte des 70 %

Format exact

  • Fichier .pt ou .pth chargé en strict=True dans l'architecture du sujet (mêmes noms de couches et formes).
  • float32 uniquement (un seul tenseur float16 ou bf16 : rejet) ; ni NaN ni infini.
  • 450 Mo maximum (450 000 000 octets) ; fichier attendu : 343 617 075 octets.
  • LoRA et adaptateurs refusionnés avant l'envoi.

Commandes

HK="env PYTHONPATH=$PWD/src \
 .venv/bin/python -m hackathon.unlearning"
$HK validate <fichier.pt>
$HK submit   <fichier.pt>          # essai à blanc
$HK submit   <fichier.pt> --yes    # envoi réel
Piège : la porte à 70 %Moins de 70 % d'accuracy sur un validation set caché : score 0. Pas d'ancre locale : garder lr bas et surveiller l'accord d'argmax sur la rétention.
  • Le serveur évalue en eval avec fp16 autocast ; les poids soumis restent float32.
  • Enregistrer state_dict(), jamais le module ; save_submission caste et valide avant d'écrire.
  • Aucun délai documenté, mais chaque tentative est journalisée.
  • Premier envoi conseillé : identity, qui doit scorer environ 0 (valide chaîne, format, délai).
